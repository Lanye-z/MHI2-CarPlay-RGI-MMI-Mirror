# MMI Mirror / CarPlay RGI V2.2 Final Design

## 1. 定位

V2.2 final-cleanup 固定采用 **Java single-writer + Native pixel-only** 架构。V2A 的 `displayable3/context70`、Native `dmdt` watchdog、`native70/java80` migration switch 只作为历史验证过程保留在 `v2-stage1.1.md` 与冻结分支中，不再属于当前生产设计。

已冻结历史基线：

```text
backup-stage1-mmi-mirror-working-20260905
backup-v2a-vehicle-tested-20260906
backup-v2.2-pre-final-cleanup-20260907
```

V2A 在 `MHI2Q_CN_AUG22_P0915` 上已经验证 MMI capture / GLES / displayable3、Unified JAR 与稳定 RGI 的基础兼容；同时证明基于 `dmdt gs` 的 Native context watchdog 不适合作为最终 ownership 机制。

---

## 2. 最终架构

```text
                    Unified carplay_hook.jar
                              │
             ┌────────────────┼────────────────┐
             ↓                ↓                ↓
        Layout/View       Context          RGI HMI
          observer       controller         bridge
             │                │                │
             └────────────────┼────────────────┘
                              ↓
                       terminal1 / ctx80
                    ctx80={98,101,102,3}
                         │            │
                  displayable98  displayable3
                         │            │
                        RGI       BaseVideo
                                      │
                                 MMI capture
```

职责固定：

```text
Java / HMI
  - Layout/View observer
  - terminal1 ownership
  - ctx72 bounce / ctx80 enter
  - ctx80 drift reconcile
  - idle -> ctx74 release
  - RGI/BaseVideo demand aggregation
  - DisplayManagerMIB2High ownership guard

Native MMI
  - 1024x480 BGRA MMI capture
  - GLES rendering
  - displayable3
  - geometry
  - BaseVideo ready lifecycle
  - capture failure / recovery
  - NO Cluster context read/write
  - NO dmdt route/reconcile/restore framework

Native RGI
  - route-guidance rendering
  - displayable98
  - NO Cluster context takeover
```

核心原则：**Cluster context 只有 Java/HMI 一个 writer；Native renderer 只拥有像素。**

## 3. Context / displayable contract

```text
ctx80 = {98,101,102,3}

98      CarPlay RGI overlay
101     OEM KDK backing
102     OEM KDK backing

```

Stock context：

```text
ctx74 = OEM map/KDK stock state
```

V2.2 不再存在 Native `context70` production path，也不再通过 launcher 参数选择 ownership。

## 4. Java ownership

`ClusterStateController` 是 terminal1 的唯一 context writer。

Composite demand：

```text
baseVideoWanted = /tmp/mmi-mirror-active
                  && /tmp/mmi-mirror-basevideo.ready

rgiWanted       = rgiPresentationActive

wantComposite   = baseVideoWanted || rgiWanted
```

进入 composite：

```text
ownershipIntent=true
      ↓
ctx72 bounce
      ↓ 180 ms
ctx80
      ↓
compositeApplied=true
```

当 BaseVideo 与 RGI 都不再需要 Cluster：

```text
ownershipIntent=false
      ↓
release guard
      ↓
ctx74
```

Java 每 250 ms 通过 `IDisplayManager.getCurrentContextID(1)` 做低成本 reconcile。它是 HMI API 检查，不是旧 Native shell watchdog。

`DisplayManagerMIB2High` guard 将物理 `switchContext` 权限限制给 controller writer thread；VIEW/OEM HMI 仍可以改变内部 Layout/View 状态，但在 ownership active 时不应把物理 Cluster 从 ctx80 拉走。

### RGI real-maneuver seam

旧 RGI 的 `BAPBridge` 在 renderer frame ready 后还会调用 `ClusterService.activateCustomRendererPipeline()`，该路径属于 displayable20/ctx74 架构，会在 JAVA80 已持有 ctx80 时将正常状态误判为失败并关闭 renderer。

V2.2 repaired candidate 固定为：

```text
RendererServer EVT_FRAME_READY
  -> ClusterStateController.setRgiPresentationActive(true)
  -> controller owns ctx72 -> ctx80

BAPBridge activatePreparedCustomRenderer
  -> no activateCustomRendererPipeline()
  -> JAVA80 delegated marker only

hide / abort / stop
  -> setRgiPresentationActive(false)
  -> no deactivateCustomRendererPipeline()
```

`ClusterService.class` 本身仍从 pinned RGI base JAR 原样继承，但 Unified JAR 中不再有其他 class 调用这两个 legacy custom-renderer pipeline 方法。

## 5. Layout/View seam

Java observer 写：

```text
/tmp/mmi-mirror-hmi.state
```

Native 只读取它来选择 geometry：

```text
CLASSIC_FULL
CLASSIC_SMALL
SPORT_FULL
SPORT_SMALL
```

BaseVideo lifecycle：

```text
/tmp/mmi-mirror-active
/tmp/mmi-mirror-basevideo.ready
```

`ready` 只有在第一个有效 MMI frame 已经成功 present 后才发布；持续 capture failure 时撤销，重新捕获到有效 frame 后再发布。

**V2.2 已删除 `/tmp/mmi-mirror-context.mode`。** Java ownership 不再有模式文件或 migration switch。

## 6. Native MMI final cleanup

final-cleanup 已从源码和最终 ARM artifact 中删除：

```text
dmdt gs/sc/dc command path
popen/system context path
route_custom_context
select_context
detect_cluster_context
reconcile_route
restore_context
route_display/context_reconcile fields
context/display/restore CLI controls
DisplayStateMachine
Stage1 context ID table
legacy main.cpp
obsolete RGI placeholder interface
```

首帧显示时序保持不变：

```text
draw -> swap -> draw -> swap
```

旧版本两次 submit 中间的 route 调用在 JAVA80 下本来就是 no-op；final-cleanup 只移除了这个 no-op，没有把首帧第二次 submit 一并优化掉。

## 10. Install / Uninstall transaction

### RGI complete = 3/3

```text
snapshot current maneuver_render
        ↓
install MMI-owned maneuver_render-rgi98
        ↓
snapshot LSD carplay_hook.jar
        ↓
install Unified JAR
        ↓
sync + commit transactions
```

### RGI absent = 0/3

```text
no RGI98 renderer install
install MMI runtime + Unified JAR
Java ctx80 ownership remains available
MMI displayable3 works; RGI native feature is absent
```

### RGI partial = 1/3 or 2/3

WARNING，并且不替换 `maneuver_render`。

Unified JAR installer 不使用固定 expected-size gate；copy integrity 仍保留 source/destination size equality 与可用时的 `cksum`。

Uninstall：

```text
RGI 0/3 -> remove MMI-owned carplay_hook.jar
RGI >0  -> restore stable RGI carplay_hook.jar + stable maneuver_render
```

安装/卸载后必须 reboot/HMI restart，再使用 RGI 或启动 MMI Mirror。

## 11. Build / release gate

Unified Java build 使用两阶段 javac：

```text
Stage 1: five core sources
classpath = real lsd.jar : OSGi : pinned RGI base JAR

Stage 2: BAPBridge only
classpath = generated classes : pinned RGI base JAR : real lsd.jar : OSGi
```

这样 core class 仍由真实 MHI2Q API gate 校验，同时 BAPBridge 能解析 pinned RGI `ClusterService` 增加的四个 accessor；`ClusterService.java` 不进入 javac source list。

CI 对候选版本执行：

```text
Native source       no dmdt / route / reconcile framework
Native artifact     exact size/hash + no dmdt context command strings
Unified Java source no context.mode migration layer
Unified JAR         exact size/hash + class major 46 + ownership guard
BAPBridge           no legacy activate/deactivate calls + JAVA80 marker/state seam
ClusterService      inherited exact class hash
RGI98 artifact      exact size/hash + no dmdt route strings
Stable RGI baseline exact known recovery hashes
Lifecycle helpers   no production dmdt context writes
Manifest            sha256sum -c passes for all three candidate artifacts
```

发布状态：

```text
Source cleanup                   PASS
Artifact rebuild/promotion       PASS
Static validation                PASS
Install/Uninstall/Rollback sim   PASS
CI                               must be GREEN
Final ctx80 vehicle test         PENDING
```

```text

/tmp/mmi-mirror-hmi.state
```

`Collect Diagnostics` 可额外收集 Unified CarPlay Java / RGI logs 与一次性 display-manager snapshot。该诊断动作不属于 runtime ownership path。

`Clear Logs` 只清可丢弃日志/self-test 文件，不删除 HMI/BaseVideo lifecycle；需要释放 BaseVideo ownership 时必须使用 `Stop`。

## 13. Vehicle validation

```text
1. Install exact candidate -> reboot/HMI restart
2. Unified JAR/controller 正常启动
3. observer 正确识别 CLASSIC/SPORT + FULL/SMALL
4. MMI displayable3 first frame -> BaseVideo ready
5. Java ctx72 bounce -> ctx80
6. VIEW 后 ctx80 ownership 保持
7. RGI displayable98 正常且箭头显示
8. real-maneuver 不再因 ctx80 != ctx74 触发 renderer abort
9. RGI + MMI 同时存在于 ctx80={98,101,102,3}
10. MMI/RGI demand 独立退出时 ownership 正确保持/释放
11. Uninstall -> reboot -> stable RGI20/JAR 恢复
```

实车验证通过后，可将 `main` 直接 fast-forward 到该 exact candidate commit，使主分支与实际车测版本保持同一 tree 和 artifact。
